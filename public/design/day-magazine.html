Day magazine · racconto editoriale del giorno

Vista alternativa alla lista verticale di attività — convivono dietro un toggle Lista ↔ Racconto. Nel racconto: l'AI scrive solo deck e intermezzi (Morning / Afternoon / Evening), i testi descrittivi delle attività sono verbatim dall'utente, mai modificati. Il pull quote è una frase ripresa letteralmente dalle note. Foto floated a destra e a sinistra alternativamente, con caption che richiamano il numero del vignette.

Note per gli sviluppatori

Princìpi non negoziabili

  • Le note attività dell'utente sono verbatim. Nessuna trasformazione: niente capitalizzazione, niente correzioni grammaticali, niente riassunti. Renderizzare con white-space: pre-wrap per preservare eventuali a-capo originali.
  • L'AI scrive solo 4 elementi: il deck in cima (1 frase, max 25 parole) e tre intermezzi uno per sezione (Morning / Afternoon / Evening, max 15 parole ciascuno). Totale: ~50–70 parole.
  • Il pull quote è una frase ripresa letteralmente da una delle attività. L'AI sceglie l'activityId e restituisce l'estratto esatto della stringa: il front-end verifica che sia effettivamente una sottostringa di activity.description, altrimenti rifiuta. Niente "frasi inventate".
  • Nessuna chiamata AI automatica. Il fetch a /api/ai/describe-day parte solo al click esplicito del bottone "Crea il racconto" (step 1). Switchare al toggle "Racconto" non genera nulla — mostra la CTA di pre-generazione.

Toggle Lista ↔ Racconto

  • Posizione: top-right del day view, sotto il banner e sopra le sezioni di attività. È un segmented control 2-stati con icona + label.
  • Default: "Lista" (la vista esistente). Persistenza in localStorage("day-view-mode") a livello viaggio: cambiando vista una volta, tutti i giorni dello stesso viaggio si aprono in quella modalità.
  • Punto arancio piccolo accanto a "Racconto" segnala che la voce richiede AI (analogo al puntino "✦" usato altrove per Go).
  • Switch a "Racconto": se il giorno ha una day_narrative valida in cache → renderizza direttamente lo stato Loaded (step 2). Se non esiste o è invalidata → mostra Pre-creation CTA (step 1). Mai chiama l'AI come effetto dello switch.
  • Switch a "Lista": torna alla vista esistente itinerary.html, immediato, senza side-effects.

Lifecycle e cache

  • Cache key: dayId + day.updatedAt. Modifica di un'attività → updatedAt nuovo → cache invalidata → al prossimo open della vista Racconto, l'utente vede la CTA di nuovo (o un'opzione "Aggiorna" sul vecchio narrative — vedi nota sotto).
  • Storage: tabella Supabase day_narratives con {dayId, dayUpdatedAt, deck, intermezzi, pullQuote, generatedAt}. Cache locale React Query / SWR opzionale per ridurre round-trip.
  • Stale-but-shown (opzionale v2): se la cache è invalidata ma esiste una versione precedente, mostrare il narrative vecchio con un banner "Le attività sono cambiate · Aggiorna il racconto" invece della CTA piena. In v1: CTA piena sempre quando non esiste un narrative valido.

Contratto API

  • Endpoint: POST /api/ai/describe-day
  • Body: { dayId, zone, type, summary, practicalNote, activities: [{id, name, time, description}] }
  • Risposta: { deck: string, intermezzi: { morning?: string, afternoon?: string, evening?: string }, pullQuote: { activityId, text }, generatedAt }
  • Cache: chiave dayId + day.updatedAt. Se l'utente modifica un'attività, la cache si invalida e l'AI ri-gira al prossimo open. Salva il payload in Supabase (table day_narratives) o in memoria server.
  • Streaming non necessario: 50–70 parole arrivano in < 1s con gpt-4o-mini. Una sola fetch, attesa, popolamento.

Selezione foto

  • Default: le prime 4 attività che hanno un photoRef da Google Places. Se < 4 disponibili, mostrane meno.
  • Alternanza right / left: pari a destra, dispari a sinistra (o viceversa — scelta visiva).
  • Niente foto per Uscita albergo e affini: euristica = se il nome contiene "uscita", "transfer", "metro", "treno", "viaggio per", salta la foto anche se disponibile.
  • Override manuale futuro: aggiungere un toggle "foto sì/no" su ogni attività (out of scope per la v1).

Anchor link

  • Il numerino nel .mag-v-head .num è un <a href="#it-{n}"> che scrolla all'itinerario in fondo.
  • Le righe dell'itinerario in fondo sono <a href="#act-{n}"> che scrollano alla vignette.
  • Usare scroll-behavior: smooth + offset per lo header sticky.

Editing

  • Deck e intermezzi: matita inline al passaggio del mouse. Click → modal o popover che mostra la frase corrente + bottoni "Rigenera con tono diverso" (più caldo / più asciutto / più curioso) o "Modifica a mano".
  • Note attività: nessuna matita nel magazine. Si editano dall'editor attività esistente (modal con form già implementato). Il magazine è una vista di lettura.
  • Rigenera tutto: bottone in fondo "Rigenera deck e intermezzi" forza un re-fetch ignorando la cache.

Mapping con il codice React

  • Component principale: features/day/DayMagazine.tsx
  • Sub-component: features/day/DayMagazineVignette.tsx (singola attività), DayMagazineSection.tsx (Morning/Afternoon/Evening + intermezzo)
  • Hook: features/day/useDayNarrative(dayId) → restituisce {deck, intermezzi, pullQuote, status: 'loading'|'ok'|'error'} con SWR/cache
  • API route: app/api/ai/describe-day/route.ts
  • Toggle vista lista / magazine: features/day/DayViewModeToggle.tsx in alto al day_view, persistito in localStorage per preferenza utente

Stati che devono funzionare

  • Pre-creation · primo accesso alla vista Racconto su un giorno senza day_narrative: CTA centrata, AI non chiamato finché l'utente non clicca
  • Loaded · tutto pronto, AI risposto, foto risolte (o cache hit al riapertura)
  • Loading · post-CTA: skeleton sui blocchi AI, contenuto utente già visibile e navigabile
  • AI failed · banner errore in cima, retry esplicito, contenuto utente intatto, possibile fallback al toggle Lista
  • Empty day · nessuna attività → empty state, AI non viene chiamato anche se l'utente è in "Racconto"
  • Pull quote validation failed · se l'AI restituisce un pull quote che non è sottostringa di una activity description, omettere il pull quote (non bloccare il resto)
  • Mobile · float disabilitato, foto inline full-width sopra ogni vignette interessato, itinerario in colonna singola
