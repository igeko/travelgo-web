Trip header · 3 stati budget

Componente di intestazione viaggio con widget budget stateful. Il widget cambia contenuto e semantica in base alla posizione temporale dell'utente rispetto al viaggio: pre-viaggio (target di risparmio), in corso (tracking speso vs previsto), completato (riepilogo finale). La logica di selezione dello stato è basata sul confronto tra today e le date del viaggio (trip.startDate, trip.endDate).

Sub: classe warn. Format: "Mancano {delta} al budget · circa {delta/giorniRimanenti}/giorno". Calcolato come budgetTotale − accantonato diviso i giorni che restano prima della partenza.

€1.180 / €1.260 previsti
Sotto budget di €80 · 15 giorni rimanenti
Stato: IN CORSO · attivo quando trip.startDate ≤ today ≤ trip.endDate
Tag: trip-state-during (icona ti-plane) + label "In corso · giorno {n} / {tot}" dove n = giorno corrente del viaggio (1-indexed), tot = giorni totali.
Valore principale: totale speso fino ad oggi (somma di activity.budgetAmount dei giorni passati + corrente, con budgetPaid = true o tutte se vuoi includere previsti).
Denominatore: "/ €{previstoAdOggi} previsti" — somma dei day.budget dei giorni 1..n (ovvero quanto avresti dovuto spendere fino ad oggi secondo la pianificazione).
Barra: width = (speso / previsto) × 100%, classe ok se ≤100%, warn se 100-115%, alert se >115%.
Sub: messaggio dinamico in base al delta:
· se speso ≤ previsto → "Sotto budget di €{delta} · {giorniRimanenti} giorni rimanenti" (classe ok)
· se 0% < eccesso ≤ 15% → "Sopra previsto di €{delta} · attenzione" (classe warn)
· se eccesso > 15% → "Oltre budget di €{delta}" (classe alert)

Note di implementazione per lo sviluppatore

1. Selezione dello stato. Il componente TripHeader riceve almeno: trip.title, trip.startDate, trip.endDate, trip.budgetTotal, trip.savedAmount (per pre-viaggio), e l'array degli days con i relativi activities contenenti budgetAmount e budgetPaid. La selezione dello stato si fa con:
const today = new Date(); const state = today < startDate ? 'pre' : today > endDate ? 'after' : 'during';

2. Computazioni per stato.
· pre: daysLeft = (startDate − today) / 1d; missing = budgetTotal − savedAmount; perDay = missing / daysLeft.
· during: currentDay = (today − startDate) / 1d + 1; previstoAdOggi = sum(days[0..currentDay-1].budget); spesoAdOggi = sum(activities con budgetPaid=true e day < today); delta = previsto − speso.
· after: spesoTotale = sum(activities.budgetAmount); delta = budgetTotal − spesoTotale.

3. Classi colore della barra e del sub. Sono indipendenti: la barra di progresso si chiama .trip-budget-bar-fill con modificatori .ok (verde), .warn (arancio), .alert (rosso). Il sub usa .trip-budget-sub.{ok|warn|alert} che colora solo il <b> interno. Le soglie dei colori sono indicate negli state-note di ogni stato.

4. Behavior link. L'intero .trip-budget è un <a href> che porta alla pagina del budget del viaggio. Hover state: valore principale si colora di arancio, chevron si sposta di 2px a destra e si colora arancio.

5. Localizzazione. I testi (Mancano, Sotto budget, Risparmiati, etc.) sono attualmente in italiano. Estrarre in i18n strings se l'app supporta più lingue.

6. Formato valute. Gli esempi mostrano €. Il componente deve usare la trip.displayCurrency (verifica in queries.js) ed eventualmente convertire da trip.localCurrency via la funzione convertCurrency di exchange.js.
