# Internazionalizzazione (i18n)

Stack: **next-intl** senza URL routing (niente `[locale]` nel path). La lingua viene rilevata automaticamente e cambiata via cookie, senza riorganizzare la struttura di `app/`.

## Decisioni architetturali

- **No URL routing** — evitato il refactor `app/` → `app/[locale]/`. Può essere aggiunto in futuro senza rompere il resto.
- **Cookie + Accept-Language** — nessuna configurazione richiesta dall'utente: il browser suggerisce la lingua, l'utente può sovrascrivere con il menu.
- **Lingue supportate** — unica fonte di verità: `i18n/locales.ts`. Aggiungere una lingua = 3 modifiche.

## File coinvolti

```
i18n/
  locales.ts          ← lingue supportate, nome cookie, labels
  request.ts          ← configurazione server next-intl

messages/
  en.json             ← stringhe in inglese (lingua primaria)
  it.json             ← stringhe in italiano

components/ui/
  LocaleSwitcher.tsx  ← dropdown/pill UI (2 varianti: chip / full)
```

## Rilevamento lingua (i18n/request.ts)

Priorità al primo valore valido tra:

1. Cookie `travelgo-locale` (impostato dal LocaleSwitcher)
2. Header `Accept-Language` inviato dal browser
3. Fallback: `"en"`

```ts
// i18n/request.ts — logica di rilevamento
const fromCookie = cookieStore.get(LOCALE_COOKIE)?.value;
const locale =
  fromCookie && SUPPORTED_LOCALES.includes(fromCookie)
    ? fromCookie
    : detectFromAcceptLanguage(headerStore.get("accept-language") ?? "");
```

L'Accept-Language parser legge `"it-IT,it;q=0.9,en;q=0.8"` e restituisce la prima tag supportata (`"it"`).

## Aggiungere una lingua

Modificare **solo** questi 3 file:

**1. `i18n/locales.ts`**
```ts
export const SUPPORTED_LOCALES = ["en", "it", "ja"] as const; // aggiungi qui

export const LOCALE_LABELS = {
  en: { name: "English",  flag: "🇬🇧" },
  it: { name: "Italiano", flag: "🇮🇹" },
  ja: { name: "日本語",   flag: "🇯🇵" }, // aggiungi qui
};
```

**2. `messages/ja.json`** — crea il file con le stesse chiavi di `en.json`

**3. `i18n/request.ts`** — nessuna modifica necessaria (usa `SUPPORTED_LOCALES` in automatico)

Il `LocaleSwitcher` mostra automaticamente la nuova lingua nel dropdown.

## Aggiungere stringhe a un componente

### Componente client (es. `features/activity/Itinerary.tsx`)

```tsx
"use client";
import { useTranslations } from "next-intl";

export function Itinerary() {
  const t = useTranslations("Itinerary");
  return <button>{t("addActivity")}</button>;
}
```

### Componente server

```tsx
import { getTranslations } from "next-intl/server";

export default async function MyPage() {
  const t = await getTranslations("MyNamespace");
  return <h1>{t("title")}</h1>;
}
```

Poi aggiungere la chiave in entrambi i file messages:

```json
// messages/en.json
{ "MyNamespace": { "title": "Hello" } }

// messages/it.json
{ "MyNamespace": { "title": "Ciao" } }
```

### Plurali (ICU)

```json
"daysCount": "{count, plural, one {# day} other {# days}}"
```

```tsx
t("daysCount", { count: 3 }) // → "3 days"
```

### Variabili interpolate

```json
"greeting": "Hi, {name}"
```

```tsx
t("greeting", { name: "Enrico" }) // → "Hi, Enrico"
```

## Date e giorni della settimana

**Non usare array hardcoded** (`DOW_EN`, `MONTH_EN`). Usare sempre `Intl.DateTimeFormat` con il locale corrente:

```tsx
import { useLocale } from "next-intl";

const locale = useLocale();

// Giorno della settimana abbreviato ("Mon" / "lun.")
const dow = new Intl.DateTimeFormat(locale, { weekday: "short" })
  .format(date)
  .toUpperCase();

// Data formattata ("15 Mar 2025" / "15 mar 2025")
const formatted = new Intl.DateTimeFormat(locale, {
  day: "numeric", month: "short", year: "numeric"
}).format(date);
```

## LocaleSwitcher

```tsx
import { LocaleSwitcher } from "@/components/ui/LocaleSwitcher";

// Compact — dropdown con globo + abbreviazione (desktop header)
<LocaleSwitcher variant="chip" />

// Full — pill affiancati con flag + nome lingua (mobile drawer)
<LocaleSwitcher variant="full" />
```

Il componente imposta il cookie con `max-age` 1 anno e chiama `router.refresh()` per rileggere il locale server-side. Nessun page reload.

## Pagine non ancora internazionalizzate

Le seguenti pagine usano ancora stringhe hardcoded. Aggiungere il namespace quando si lavora su di esse:

- `app/(app)/trips/page.tsx` — lista viaggi
- `app/(app)/profile/page.tsx` — profilo utente
- `app/(marketing)/page.tsx` — landing page
- `app/(auth)/login/page.tsx` — login
